## Concrete Executor Binding Contract

Choose Option A: an exact binding already exists before activation-authorization
issuance. The existing explicit `ProductionAppBindingProvisioner` and
`ProductionExecutorBindingController` remain the binding owners. The ceremony
coordinator only resolves and reserves the exact handle; it never constructs a
real executor or binds implicitly.

```ini
CONCRETE_EXECUTOR_BINDING_ID_REQUIRED=YES

EXECUTOR_BINDING_PROVISION_EQUALS_INVOCATION_AUTHORIZATION=NO
EXECUTOR_BINDING_PROVISION_EQUALS_EXECUTION=NO
```

Issuance requires an unexpired handle whose receiver, enablement, transport,
model, executor identity, and runtime scope match the request. Authorization
expiry must not exceed binding expiry. Reservation is ceremony-local ownership
of that existing handle, not a second binding.

```ini
EXECUTOR_BINDING_RESERVATION_LIFETIME=MINIMUM_OF_BINDING_EXPIRES_AT_AND_ACTIVATION_AUTH_EXPIRES_AT_MAXIMUM_300_SECONDS
```

Application restart loses the in-memory handle. A durable issued authorization

## Cancellation, Revocation, and State Machine

Cancellation terminates an unused issued authorization. Revocation terminates a
claimed authorization before durable consume wins. Neither rewrites completed
history.

