Control flow:

```text
validate explicit receiver_id and request_id
-> atomically acquire the one lifecycle slot for request_id
-> if occupied: DENY PRODUCTION_REQUEST_CONCURRENCY_LIMIT
-> resolve the pre-existing explicit binding
-> invoke the governed host action once
-> perform EA-4E.53 binding teardown once
-> finally: release the lifecycle slot for the same request_id
```

Admission therefore precedes binding lookup. Release is outside and
independent of binding teardown, so a teardown denial or exception cannot
leave stale admission occupancy.
