## Lessons

1. **Explicit parameters prevent mutation**: By passing `task_payload` and `expected_output` as explicit function parameters, the harness no longer requires module-global mutation to switch between qualification markers.

2. **Pre-execution validation is essential**: The authorized task text is compared against the constructed execution task text before any receiver execution, ensuring byte-for-byte equality.

3. **Historical preservation**: The full sequence of defects and corrections (EA-4E.25 → 25A → 25R → 25R-A → 25R-B → 25R2) is preserved in the evidence, not erased.

4. **Single-shot discipline**: Exactly one live OpenCode task was performed, with authorization consumed and second use blocked without re-execution.
