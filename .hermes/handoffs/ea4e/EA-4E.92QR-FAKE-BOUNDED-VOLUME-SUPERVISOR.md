# EA-4E.92QR Fake Bounded Volume Supervisor

The independent 92QQ review accepted the source/ABI shape of the 92QP
read-only probe but found its deadline and ceremony are entry checks only.
This checkpoint adds an unwired Python supervisor candidate. It binds an
absolute non-symlink executable path and SHA-256, expected ProgramData path,
operator SID, ceremony ID, and UTC deadline; consumes one process-local
attempt before checking; then forms only the native-volume argv. It uses a
five-second-or-remaining-deadline wait, bounded stdout/stderr, a sanitized
environment, no shell or stdin, and kill/wait on timeout or output failure.
The deadline is checked again after hashing. Nonzero exits are returned as
data, not converted into a positive result.

Focused fake-process tests passed 10/10; the adjacent inert matrix passed
153/153 before staging. All process starts in these tests use an injected
fake, not the 92QP executable. The supervisor is not wired to an app command
or issuer, and no native mode was run.

This is not durable one-shot accounting or trusted operator authorization.
The worktree/output path is mutable by the local app account, so hashing it
before a path-based spawn has a replacement window and does not meet the
protected-install contract. The candidate does not authenticate the
ceremony, parent topology, actual volume target, effective rights, or a
process tree. It needs independent source review, protected executable
provenance, an external authorization/ledger, and an exact bounded native
run approval before any qualification attempt. Strict 92AT remains REJECT;
issuer, real Kilo/OpenCode handoff, and production remain HOLD. No Docker,
receiver/model, GPU, ComfyUI, or production action occurred.
